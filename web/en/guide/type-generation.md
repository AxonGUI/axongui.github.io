# Type generation: give `Axon.Xxx` real signatures

`Axon` only knows its controllers at runtime (whatever the page registers), so it is declared as `any`:
`Axon.Greeter.greet(` completes nothing and mistyped calls compile fine.

`axon-gui types` reads the runtime registry and emits a type file that closes that gap:

```bash
axon-gui types
```

| Direction | Input | Output | What you get in the editor |
| --- | --- | --- | --- |
| Python → TS | classes registered with `@AxonController` + annotations | `web/src/axon.generated.ts` | `Axon.Greeter.greet(` completes parameter names and types |
| JS → Python | `AxonController.register("DocsJS", { … })` | `controller/js_controllers.pyi` | `api.DocsJS.note(` completes in Python |

The first direction is generated by default; the second needs `--js` (it parses frontend sources with the TypeScript compiler).

## Where the files go

One command writes both directions, to these two paths (relative to the project root — it is detected even when you
run from `web/`):

| Artifact | Default path | Override | Notes |
| --- | --- | --- | --- |
| Python → TS | `web/src/axon.generated.ts` | `--ts-out <file>` | Parent dirs are created; commit it |
| JS → Python | `controller/js_controllers.py` | `--py-out <file>` | A **runnable .py**, not a `.pyi` |

```bash
axon-gui types                      # both directions (default)
axon-gui types --check              # CI: verify both
axon-gui types --only ts            # TS only
axon-gui types --ts-out app/types/axon.ts --py-out app/js_api.py   # custom paths (--out is an alias)
```

Two hard requirements:

- **The TS file must be inside your tsconfig's program** (under `src/` is easiest). It works through
  `declare module "axon-gui"`; if nothing includes it, nothing happens.
- **The Python file's directory must be importable** (give `controller/` an `__init__.py`), because `connect()` is
  real runtime code.

## What gets generated

```python
from axon import AxonController

@AxonController("MainView")
class Greeter:
    counter: int = 0

    def greet(self, name: str, times: int = 1) -> str:
        return "、".join([f"你好，{name}！"] * times)
```

```ts
// web/src/axon.generated.ts — generated, do not edit
export interface AxonRegistry {
  /** Window: MainView */
  Greeter: {
    greet(name: string, times?: number): Promise<string>;
    counter: number;
  };
}

declare module "axon-gui" {
  interface AxonControllers extends AxonRegistry {}
}
```

`AxonControllers` is a typing seam reserved by `axon-gui`. **Without a generated file it is an empty interface and
`Axon` stays `any`**, so this is purely additive — existing projects are unaffected.

## Effect

```ts
// Before: everything is any
const text = await Axon.Greeter.greet("Axon", 2);

// After: names, types and return values; mistakes fail to compile
const text: string = await Axon.Greeter.greet("Axon", 2);
await Axon.Greeter.greet(42);     // ✗ number is not assignable to string
await Axon.Greeter.grete("Axon"); // ✗ no such method
```

The async layer is handled too: both `def` and `async def` become `Promise` in JS, so the generated signature is always
`Promise<ReturnType>` and `await` gives you the value.

## Hover to see the generated types

That `declare module` block is exactly what the generator writes; hover `Axon`, `add` and `sum` to watch the type travel.

```ts twoslash
import { Axon } from "axon-gui";

declare module "axon-gui" {
  interface AxonControllers {
    DemoController: {
      add(a: number, b: number): Promise<number>;
    };
  }
}

async function demo() {
  const sum = await Axon.DemoController.add(1, 2);
  return sum.toFixed(1);
}
```

## When to regenerate

Whenever controller signatures change: new/removed methods, renamed or retyped parameters (defaults become optional),
new controllers, changed return types.

```bash
axon-gui types        # manual
axon-gui types --check  # CI: fail when the generated file is stale
```

Or let the Vite plugin do it while you work (dev start and on save, ~150 ms):

```ts
import { axonTypes } from "axon-gui/vite-plugin";
export default defineConfig({
  plugins: [vue(), axonTypes({ args: ["--controllers", "controller"] })],
});
```

::: tip `vite build` does not run the generator
It needs a Python environment and builds should not. The plugin only attaches to `serve`; builds use the committed
generated file, and CI catches drift with `--check`.
:::

All three official templates (Vue / React / Angular) ship `npm run types` and `npm run types:check`.

## Reverse direction: calling frontend code from Python

Frontend controllers are runtime-known too, so Python only gets types where you ask for them. The generator reads:

```ts
AxonController.register("DocsJS", {
  value: 7,
  mirror(payload: { hello: string }, label: string) {
    return { mirrored: payload, label };
  },
});
```

```bash
axon-gui types --js web/src
```

```python
class DocsJS(Protocol):
    value: float
    def mirror(self, payload: dict[str, Any], label: str) -> dict[str, Any]: ...
    def note(self, text: str) -> None: ...

def connect(web_name: str = "*") -> AxonJsApi: ...
```

```python
from controller.js_controllers import connect

api = connect("MainView")
api.DocsJS.note("hello")
mirrored = api.DocsJS.mirror({"hello": "world"}, "tag").result(5)
```

Python has no module augmentation like TypeScript, hence the `connect()` entry point. `Axon(...)` itself is still `any`
and you can keep using it.

## What it does not do

- **No runtime validation** — types are editor/compile-time only.
- **No annotations, no completion** — unannotated members become `any` / `Any`.
- **Plain JS projects only get method names** — parameters degrade to `any`.
- **Cross-window is a union** — `AxonCross.web("charts").DocsJS` sees every window's controllers, not per-window ones.
- **Dynamic registration names are skipped** — the generator only understands string literals.

## Which annotations pay off

| Python | Generated TS |
| --- | --- |
| `def f(a: int, b: str = "x") -> bool` | `f(a: number, b?: string): Promise<boolean>` |
| `def f(items: list[str]) -> dict[str, int]` | `f(items: Array<string>): Promise<Record<string, number>>` |
| `def f(x: int \| None = None) -> None` | `f(x?: number \| null): Promise<null>` |
| `counter: int = 0` | `counter: number` |
| `TypedDict` / dataclass / pydantic model | inline object `{ … }` |
